# V2 platform baseline for local-first framework integration

This record freezes the platform facts used before importing application-protocol histories. It is
evidence for Task 1 of the local-first framework implementation plan, not a release or publication
authorization.

The implementation branch was created directly from the merge commit. ADR-0001 and the execution
plan were then added without changing production source or the workspace graph.

During baseline verification, the process-level relay driver reproduced a teardown-only
`ConnectionReset` after both cross-version datagrams had already been verified. Commit
`1693c0783cb7b82e7fcebc65b9cbb4f7b9b6b233` narrows the driver to accept only
`ConnectionReset`/`BrokenPipe` at that post-verification join point. Timeout, connection-refused,
handshake, send, receive, payload, and subprotocol failures remain errors. This correction changes
no relay wire bytes or production dependency edge.

## Local validation

The following commands completed successfully from a clean implementation worktree. Generated
build evidence remained under ignored `target/` directories.

```text
cargo make format-check
git diff --check
scripts/tests/check-workspace-architecture.sh
cargo test --locked --manifest-path compat/relay-v1-interop/Cargo.toml
cargo clippy --locked --manifest-path compat/relay-v1-interop/Cargo.toml --all-targets -- -D warnings
scripts/tests/check-relay-compatibility.sh --live
scripts/run-v2-semver-checks.sh
```

The live relay gate exercised current and exact upstream `v1.0.3` clients against both current and
upstream servers while forcing both `iroh-relay-v1` and `iroh-relay-v2`. The semver gate reported no
required update for `iroh`, `iroh-base`, `iroh-runtime`, `iroh-resolver`, `iroh-dns`,
`iroh-dns-server`, or `iroh-relay` against the post-cut baseline.
